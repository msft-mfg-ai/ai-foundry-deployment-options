02

Configure four Entra objects.

The interactive client, blueprint, child identity, and resource API each have a distinct job. Combining their responsibilities is the fastest route to an audience or consent failure.

A · Teams bot SSO application

Interactive client

  • Single-tenant app registration with a service principal.
  • Manifest resource: api://botid-<bot-app-id>.
  • Expose its own access_as_user
  • Redirect URI: https://token.botframework.com/.auth/web/redirect.
  • Enable access-token and ID-token issuance.
  • Client secret is stored only in hosted configuration and Azure Bot OAuth settings.
B · Agent Identity blueprint

Parent authorization policy

  • Identifier URI: api://<blueprint-client-id>.
  • Expose admin-consent scope access_as_user.
  • Preauthorize the Teams bot SSO application for that scope.
  • Declare Graph and MCP delegated permissions in requiredResourceAccess.
  • Grant administrator consent on the blueprint.
  • Add scope-only inheritable permissions for every downstream resource.
C · Child Agent Identity

Runtime actor

  • Created and managed by Foundry; do not create a secret.
  • Its app ID becomes client_id
  • The blueprint T1 identifies it through the FMI path in sub.
  • The final resource token contains the child ID in appid and the human in oid.
D · Downstream API

Graph or custom MCP resource

  • Graph example: delegated User.Read.
  • MCP example: expose mcp.access on the MCP API registration.
  • The blueprint receives and inherits each delegated permission.
  • Tokens remain audience-bound: a Graph token cannot authorize the MCP API.
The Foundry-managed fmi-fic belongs to the blueprint. The hosted runtime requests api://AzureADTokenExchange/.default using the blueprint client ID; Foundry supplies the managed credential and binds the resulting assertion to the child identity.

RBAC is not OAuth consent.

Azure roles authorize calls to Foundry and state services. Entra delegated permissions authorize access to Graph or MCP. The deployment needs both layers.
