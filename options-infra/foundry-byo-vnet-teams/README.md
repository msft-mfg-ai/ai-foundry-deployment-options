# Foundry BYO VNet + Teams agent and web tab

BYO VNet Foundry deployment that creates three independently installable Teams
packages per agent:

- **direct** — Azure Bot Service calls the Foundry activity protocol directly;
- **proxy** — Azure Bot Service calls the VNet-attached proxy bot endpoint;
- **tab** — Teams renders a fixed-agent React/Fluent web chat hosted by the
  proxy. This package has no bot capability and does not use Azure Bot Service.

All packages use the icons under [`teams-app/`](./teams-app/). Their manifests
are generated by Bicep and packaged by the postprovision hook.

## Architecture

```text
Direct bot: Teams -> Bot Service -> Foundry activityprotocol
Proxy bot:  Teams -> Bot Service -> proxy /api/messages -> Foundry
Web tab:    Teams -> proxy /chat/.../ui -> Teams SSO -> OBO -> Foundry
```

The tab package uses the shared backend Entra app. Teams JS obtains a delegated
`access_as_user` token for that app, the proxy validates it, and the proxy
performs OBO for Azure AI Foundry. One package is shared by all users, while
authorization and Foundry calls remain per-user.

## Deployment

```bash
azd up
```

The provision step deploys the infrastructure. The **postprovision** hooks then:

1. Create the configured Foundry agents.
2. Register the proxy's `/signin-oidc` and `/chat/auth/callback` redirect URIs
   on the shared backend app.
3. Create/update the per-agent FIC and Bot Service resources.
4. Write and zip the `direct`, `proxy`, and `tab` manifests.

Packages are written as:

```text
teams-app/build/teams-app-<agent>-direct.zip
teams-app/build/teams-app-<agent>-proxy.zip
teams-app/build/teams-app-<agent>-tab.zip
```

Sideload the desired package in Teams. Installing the `tab` ZIP alone is
enough for the web-chat experience; its corresponding Bot Service resources
are not involved.

## Customizing the manifest

The manifests are Bicep object literals in [`main.bicep`](./main.bicep) and are
emitted together through `TEAMS_MANIFESTS`.

Replace [`teams-app/color.png`](./teams-app/color.png) (192×192) and [`teams-app/outline.png`](./teams-app/outline.png) (32×32, transparent + white) with your own branding before publishing.

## Parameters

| Name | Default | Notes |
|---|---|---|
| `projectsCount` | `1` | Foundry projects to create |
| `apiServices` | `[]` | External MCP/OpenAPI services |
| `teamsProxyImage` | `ghcr.io/karpikpl/foundry-teams-bot-service-proxy:0.12.9` | Proxy/web-tab image; override with the `TEAMS_PROXY_IMAGE` azd environment value |

## Key outputs

| Output | Purpose |
|---|---|
| `TEAMS_MANIFESTS` | Per-agent `direct`, `proxy`, and `tab` manifests consumed by postprovision |
| `AGENT_APP_REGS_JSON` | Per-agent proxy app registrations |
| `PROXY_FQDN` | Public proxy origin used by bot endpoints and tab URLs |
| `TEAMS_APP_BACKEND_ID` | Shared Entra app used by the tab for Teams SSO/OBO |

## Troubleshooting

### `Teams silent SSO failed before reaching the bot. {"code":"invokeerror"}`

The per-agent AAD app registration is missing the implicit grant
issuance flags. Verify with:

```bash
az ad app show --id <agent-appId> --query "web.implicitGrantSettings"
```

Both `enableIdTokenIssuance` and `enableAccessTokenIssuance` must be
`true`. If either is `false`, PATCH them via Graph (the `az ad app
update --set` form doesn't accept nested `web.*` paths):

```bash
APP=<agent-appId>
az rest --method PATCH \
  --url "https://graph.microsoft.com/v1.0/applications(appId='$APP')" \
  --headers "Content-Type=application/json" \
  --body '{"web":{"implicitGrantSettings":{"enableIdTokenIssuance":true,"enableAccessTokenIssuance":true}}}'
```

`preprovision-multi-agent.{sh,ps1}` step 4b now sets these
automatically on every per-agent reg, so re-running `azd provision`
fixes any drift.

### Teams slash-command click pastes a sentence instead of `/cmd`

In M365 Copilot custom-engine-agent context, Teams treats
`bots[].commandLists` as "Prompt Suggestions" and pastes the
**description** field into the compose box (not `title`).
`publish-teams-agent.sh` therefore puts the literal `/cmd` in
`description` and a human-friendly label in `title`.
Re-upload the sideloaded `.zip` (Teams caches the manifest
per install — re-publishing via Foundry won't refresh devices
that already have the app sideloaded).
