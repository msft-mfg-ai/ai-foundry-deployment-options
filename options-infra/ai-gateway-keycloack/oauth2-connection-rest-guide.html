00

What the connection actually does

Foundry stores the OAuth client credentials in a project connection. Before calling APIM, Foundry posts those credentials to the configured token endpoint. It then forwards the returned access token as a bearer token. APIM validates the token and uses its own managed identity for the outbound call to the model backend.

Foundry agent-> custom-oauth-> OIDC token endpoint-> APIM /inference-keycloak-> Model backend
Two independent identities: the OAuth token secures Foundry-to-APIM. APIM's managed identity secures APIM-to-Foundry or APIM-to-Azure OpenAI.

02

Create the Entra application with Graph REST

The original operational setup created one application, exposed the AI.Gateway permission, added a client secret, and used the same application as the client requesting its own resource token.

2.1 Create the application object

POST graph.microsoft.com/v1.0/applications
APP_RESPONSE="$(curl -fsS -X POST \
  "https://graph.microsoft.com/v1.0/applications" \
  -H "Authorization: Bearer $GRAPH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "displayName": "AI.Gateway",
    "signInAudience": "AzureADMyOrg"
  }')"

export APP_OBJECT_ID="$(jq -r .id <<<"$APP_RESPONSE")"
export CLIENT_ID="$(jq -r .appId <<<"$APP_RESPONSE")"
export SCOPE_ID="$(uuidgen)"

2.2 Expose the identifier URI and scope

PATCH application object
curl -fsS -X PATCH \
  "https://graph.microsoft.com/v1.0/applications/$APP_OBJECT_ID" \
  -H "Authorization: Bearer $GRAPH_TOKEN" \
  -H "Content-Type: application/json" \
  -d "$(jq -nc \
    --arg clientId "$CLIENT_ID" \
    --arg scopeId "$SCOPE_ID" '{
      identifierUris: ["api://" + $clientId],
      api: {
        oauth2PermissionScopes: [{
          id: $scopeId,
          value: "AI.Gateway",
          type: "Admin",
          isEnabled: true,
          adminConsentDisplayName: "Access AI Gateway",
          adminConsentDescription: "Allows the application to call the AI Gateway."
        }]
      }
    }')"

2.3 Create the service principal and client secret

POST service principal + addPassword
curl -fsS -X POST \
  "https://graph.microsoft.com/v1.0/servicePrincipals" \
  -H "Authorization: Bearer $GRAPH_TOKEN" \
  -H "Content-Type: application/json" \
  -d "$(jq -nc --arg appId "$CLIENT_ID" '{appId:$appId}')" >/dev/null

SECRET_RESPONSE="$(curl -fsS -X POST \
  "https://graph.microsoft.com/v1.0/applications/$APP_OBJECT_ID/addPassword" \
  -H "Authorization: Bearer $GRAPH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "passwordCredential": {
      "displayName": "Foundry ModelGateway"
    }
  }')"

export CLIENT_SECRET="$(jq -r .secretText <<<"$SECRET_RESPONSE")"
export TOKEN_URL="https://login.microsoftonline.com/$TENANT_ID/oauth2/v2.0/token"
export TOKEN_SCOPE="api://$CLIENT_ID/.default"
Secret boundary: Graph returns secretText only once. Store it in a secure deployment variable or secret store. Never put it in source control, Bicep outputs, command history, or logs.
03

Create the Foundry connection with ARM REST

The connection is a child resource of the Foundry project. The properties: any(...) construct used by the Bicep module emits this same preview resource shape.

PUT project connection / 2025-04-01-preview
CONNECTION_URL="https://management.azure.com/subscriptions/$SUBSCRIPTION_ID/resourceGroups/$RESOURCE_GROUP/providers/Microsoft.CognitiveServices/accounts/$FOUNDRY_ACCOUNT/projects/$FOUNDRY_PROJECT/connections/$CONNECTION_NAME?api-version=2025-04-01-preview"

MODELS='[
  {
    "name": "gpt-4o-mini",
    "properties": {
      "model": {
        "name": "gpt-4o-mini",
        "version": "2024-07-18",
        "format": "OpenAI"
      }
    }
  }
]'

curl -fsS -X PUT "$CONNECTION_URL" \
  -H "Authorization: Bearer $ARM_TOKEN" \
  -H "Content-Type: application/json" \
  -d "$(jq -nc \
    --arg target "$APIM_TARGET" \
    --arg clientId "$CLIENT_ID" \
    --arg clientSecret "$CLIENT_SECRET" \
    --arg tokenUrl "$TOKEN_URL" \
    --arg scope "$TOKEN_SCOPE" \
    --arg models "$MODELS" '{
      properties: {
        category: "ModelGateway",
        target: $target,
        authType: "OAuth2",
        isSharedToAll: true,
        credentials: {
          clientId: $clientId,
          clientSecret: $clientSecret
        },
        tokenUrl: $tokenUrl,
        scopes: [$scope],
        metadata: {
          deploymentInPath: "true",
          inferenceAPIVersion: "2024-10-21",
          models: $models,
          customHeaders: "{\"x-ms-foundry-models\":\"byom\"}"
        }
      }
    }')"
Metadata values are strings. The model array is serialized JSON inside metadata.models. deploymentInPath: "true" matches APIM routes such as /openai/deployments/{model}/chat/completions.

Read back the resource

GET connection
curl -fsS "$CONNECTION_URL" \
  -H "Authorization: Bearer $ARM_TOKEN" |
  jq '{
    name,
    category: .properties.category,
    authType: .properties.authType,
    target: .properties.target,
    tokenUrl: .properties.tokenUrl,
    scopes: .properties.scopes
  }'
04

Validate the OAuth token in APIM

APIM must validate the exact issuer and audience carried by the access token. The first Entra test revealed that the token's aud was the raw application ID, not the api://... identifier URI. The policy was updated to accept that observed value.

APIM validate-jwt policy
<validate-jwt
    header-name="Authorization"
    require-scheme="Bearer"
    failed-validation-httpcode="401"
    failed-validation-error-message="Invalid OAuth access token">
  <openid-config
      url="https://login.microsoftonline.com/${tenant-id}/v2.0/.well-known/openid-configuration" />
  <audiences>
    <audience>${client-id}</audience>
  </audiences>
</validate-jwt>

This sample isolates external-provider validation on the dedicated /inference-keycloak API. Its API policy includes the sample-owned oidc-token-validation fragment; the shared /inference API remains unchanged.

Dedicated API policy
var policyXml = replace(
  loadTextContent('../modules/apim/policy-per-model.xml'),
  '{JWT_VALIDATION}',
  '<include-fragment fragment-id="oidc-token-validation" />'
)

inferenceAPIName: 'inference-api-keycloak'
inferenceAPIPath: 'inference-keycloak'
05

Prove the path before running an agent

5.1 Request the same token Foundry will request

OAuth2 client credentials
ACCESS_TOKEN="$(curl -fsS \
  --data-urlencode grant_type=client_credentials \
  --data-urlencode "client_id=$CLIENT_ID" \
  --data-urlencode "client_secret=$CLIENT_SECRET" \
  --data-urlencode "scope=$TOKEN_SCOPE" \
  "$TOKEN_URL" | jq -r .access_token)"

test -n "$ACCESS_TOKEN"

5.2 Inspect issuer, audience, and client identity

JWT payload inspection / diagnostic only
JWT_PAYLOAD="$(cut -d. -f2 <<<"$ACCESS_TOKEN" | tr '_-' '/+')"
printf '%s' "$JWT_PAYLOAD" |
  awk '{ l=length($0)%4; if (l==2) print $0"=="; else if (l==3) print $0"="; else print $0 }' |
  base64 -d 2>/dev/null |
  jq '{iss, aud, azp, appid, scp, roles, exp}'

5.3 Call APIM directly

Gateway smoke test
curl -i -X POST \
  "$APIM_TARGET/openai/deployments/gpt-4o-mini/chat/completions?api-version=2024-10-21" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {"role": "user", "content": "Reply with: OAuth gateway works"}
    ]
  }'
  • Token endpoint returns an access token.
  • JWT iss matches the OIDC discovery issuer.
  • JWT aud matches the APIM policy audience.
  • Direct APIM request returns HTTP 200.
  • Foundry agent using custom-oauth/{model} completes.
06

Substitute Keycloak for Entra

The Foundry REST resource does not care which standards-compliant OAuth2 provider issues the token. Keep the connection payload shape and replace the provider-specific values.

FieldKeycloak value
clientIdfoundry-model-gateway
clientSecretConfidential client secret generated before deployment.
tokenUrlhttps://{host}/realms/ai-gateway/protocol/openid-connect/token
scopes["AI.Gateway"]
audienceai-gateway, emitted by an audience mapper.
required claimazp=foundry-model-gateway
Keycloak policy fragment
<validate-jwt header-name="Authorization" require-scheme="Bearer">
  <openid-config
      url="${keycloakUrl}/realms/${keycloakRealm}/.well-known/openid-configuration" />
  <audiences><audience>ai-gateway</audience></audiences>
  <required-claims>
    <claim name="azp" match="all">
      <value>foundry-model-gateway</value>
    </claim>
  </required-claims>
</validate-jwt>
